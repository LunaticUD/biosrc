## 从Fastq到计数表
1. conda搭建环境
	sra-tools:从 NCBI 下载公开测序数据（fastq）
	trim_galore:去除接头序列、低质量碱基
	star:把 read 比对回参考基因组
	subread(含featureCounts):统计每个基因的 read 数
	multiqc:汇总质控和比对报告
2. RNA-seq转录组测序原理
	1) 提取RNA
	2) 打断成小片段
	3) 上机测序
	4) 比对回基因组
	5) 计数
> 落在某个基因区域的 read 越多，说明这个基因表达量越高。

4. 五步表达矩阵
	1) Step 1：建文件夹
	```bash

	mkdir -p ~/data/RNAseq/star_index_mm10
	mkdir -p ~/data/RNAseq/gtf

	# 存放去接头（trimming）结果，每个样本单独一个文件夹

	# 存放比对结果

	```
	2) Step 2：去除接头序列
	```bash
	# 引入的接头（adapter）序列和低质量碱基会干扰后续比对，必须先清理掉
	trim_galore --fastqc --paired --cores 8 \
	  ~/data/RNAseq/GSE259357/raw/SRR28119110_1.fastq.gz \
	  ~/data/RNAseq/GSE259357/raw/SRR28119110_2.fastq.gz \
	  -o ~/data/RNAseq/GSE259357/trimmed/SRR28119110
	# --fastqc
	# trimming 完成后自动跑一次质控报告；
	# --paired
	# 告诉软件这是双端数据，R1/R2 两个文件要配对处理；
	# --cores 8
	# 使用 8 个核心加速。
	# 查看输出
	ll ~/data/RNAseq/GSE259357/trimmed/SRR28119110 | grep "fq.gz"
	# SRR28119110_R1_001_val_1.fq.gz 和 SRR28119110_R2_001_val_2.fq.gz
	```
	3) Step 3：比对到参考基因组
	```bash
	# STAR 把清理后的 read 比对回小鼠基因组
	STAR --genomeDir ~/data/RNAseq/star_index_mm10 \
	  --runThreadN 20 --readFilesIn \
	  ~/data/RNAseq/GSE259357/trimmed/SRR28119110/SRR28119110_1_val_1.fq.gz \
	  ~/data/RNAseq/GSE259357/trimmed/SRR28119110/SRR28119110_2_val_2.fq.gz \
	  --outSAMtype BAM SortedByCoordinate \
	  --outSAMunmapped Within \
	  --outSAMattributes Standard \
	  --readFilesCommand zcat \
	  --outFileNamePrefix ~/data/RNAseq/GSE259357/aligned/SRR28119110
	# --outSAMtype BAM SortedByCoordinate
	# 直接输出按坐标排序好的BAM文件，省去后续手动排序的麻烦；
	# --readFilesCommand zcat
	# 因为输入是.gz压缩文件，需要告诉STAR用zcat先解压再读取；
	# --runThreadN
	# 线程数，根据服务器实际核心数调整，别一股脑设太大占满整台机器。
	# 查看输出
	ll ~/data/RNAseq/GSE259357/aligned/SRR28119110 | grep "bam"
	# SRR28119110_trimmedAligned.sortedByCoord.out.bam
	# 报错，索引不一致，自己进行构建
	STAR \
	    --runThreadN 20 \                          # 使用 12 个线程并行计算
	    --limitGenomeGenerateRAM 200000000000 \    # 内存上限设为 200GB
	    --runMode genomeGenerate \                 # 指定当前模式为"生成基因组索引"
	    --genomeDir ~/data/RNAseq/star_index_mm10_2.7.11b \   # 索引文件的输出目录
	    --genomeFastaFiles ~/data/RNAseq/reference/GRCm38.primary_assembly.genome.fa \  # 基因组 FASTA 文件
	    --sjdbGTFfile ~/data/RNAseq/gtf/gencode.vM25.annotation.gtf                  # 基因注释 GTF 文件
	```
	4) Step 4：定量——统计每个基因的read数
	```bash
	# featureCounts 把落在每个基因区间里的 read 数出来
	cd ~/data/RNAseq
	featureCounts -T 8 -p -B -C \
	  -t exon \
	  -g gene_name \
	  -s 0 \
	  -a reference/gencode.vM25.annotation.gtf \
	  -o GSE259357/aligned/SRR28119110/SRR28119110_featureCounts_exon.txt \
	  GSE259357/aligned/SRR28119110/Aligned.sortedByCoord.out.bam
	# -p
	# 开启 paired-end 模式
	# -B
	# 只有两端 read 都比对到基因组的 fragment 才计数
	# -C
	# 排除嵌合比对（chimeric alignment）的 fragment
	# -t exon
	# 以外显子（exon）为单位统计；
	# -g gene_name
	# 最终按基因名（而非转录本）汇总计数；
	# -s 0
	# 链特异性参数，0 表示不区分链方向（unstranded）。这个参数一定要根据你实际的建库方式来设置，如果你的建库是链特异性的（strand-specific），设错了会导致计数严重失真，不确定的话可以先用 RSeQC 之类的工具检测一下建库类型。
	# 查看计数结果
	ll ~/data/RNAseq/GSE259357/aligned/SRR28119110/ | grep "exon"
	# 基因名、染色体、起始位置、终止位置、链方向、基因长度、read 计数
	```

3. 数据准备
	1) 合并所有样本的count文件
	```R
	# SRR28119110_featureCounts_exon.txt
	# 找到所有样本的 featureCounts 结果文件
	count_file_path <-"~/Tutorials/RNAseq/GSE259357/aligned"
	file_names <- list.files(count_file_path, pattern ="featureCounts_exon\\.txt$",
	                         recursive =TRUE, full.names =TRUE)
	# 逐个读入每个样本的count文件（featureCounts输出默认第1列是基因名，第7列是count数，跳过前1行注释）
	count_list <- lapply(file_names,function(f){
	  tmp <- fread(f, skip =1, data.table =FALSE)
	  sample_name <- gsub("_featureCounts_exon.*","", basename(f))
	  data.frame(Gene = tmp[[1]], Count = tmp[[7]])|> setNames(c("Gene", sample_name))
	})
	# 以基因名为key，把所有样本的count合并成一张矩阵
	counts_raw <- Reduce(function(x, y) merge(x, y, by ="Gene"), count_list)
	rownames(counts_raw)<- counts_raw$Gene
	counts_raw <- counts_raw[,-1]
	# 保存合并好的原始表达矩阵，以后直接读这个文件就行，不用每次重新合并
	fwrite(counts_raw,"counts_raw.tsv", sep ="\t", row.names =TRUE)
	```

## 从差异基因到富集通路
1. 常用的通路数据库
	1) Gene Ontology（GO）
	> 分子功能（MF, Molecular Function）：分子层面具体在做什么，比如 ATP 结合、蛋白激酶活性；
	> 生物学过程（BP, Biological Process）：多个分子功能协同完成的更宏观的生物学目标，比如细胞周期调控、免疫应答、细胞凋亡；
	> 细胞组分（CC, Cellular Component）：基因产物在细胞里的哪个位置发挥作用，比如细胞核、细胞质、线粒体膜。
	2) KEGG（京都基因与基因组百科全书）
	> KEGG整合了基因组、化合物、通路等多维信息，常用的子模块包括：通路图谱（pathway maps）、跨物种同源基因功能分组（KO）、疾病相关通路（KEGG Disease）、药物与酶信息、化合物结构信息。做转录组分析最常用的就是KEGG的pathway富集。
	3) MSigDB（分子特征数据库）
	> MSigDB 是目前收录最全的通路数据库，把 GO、KEGG 以及其他很多来源的基因集都整合在了一起，堪称"一站式"富集分析资源，里面包含 Hallmark（核心生物学过程）、C2（来自 KEGG/Reactome/文献的通路集）、C5（GO 分组）、C7（免疫特征）、C8（细胞类型特征）等多个子集，覆盖面比单独的 GO 或 KEGG 都更广。
2. 两种统计方法：ORA 和 GSEA
	1) 过表达分析（ORA, Over-Representation Analysis）
	> ORA 先用一个固定阈值（比如padj < 0.05且|log2FoldChange| > 1）筛出一批差异基因，再用统计检验（通常是超几何检验/Fisher精确检验）看这批基因是否在某个通路里"扎堆"出现的比例明显高于随机水平
	2) 基因集富集分析（GSEA, Gene Set Enrichment Analysis）
	> GSEA 不设阈值、不做预先筛选，而是把全部基因按某个指标（通常是 log2FoldChange）从大到小排序，看某个通路里的基因是不是集中出现在排序列表的头部或尾部。

5. 基因集富集分析（GSEA）
	1) GO 富集（GSEA 方法）
	```R
	# GSEA 需要一个按表达变化幅度排好序、并且带有基因名的向量作为输入：
	# 按log2FoldChange从大到小排序
	deg_order_fc<-deg[order(-log2FoldChange)]
	logfc<-deg_order_fc$log2FoldChange
	names(logfc)<-deg_order_fc$V1 # 基因名作为向量的名字

	# 跑GSEA（小鼠用org.Mm.eg.db；人用org.Hs.eg.db；大鼠用org.Rn.eg.db）
	enrich_go_gsea<-gseGO(geneList=logfc, OrgDb=org.Mm.eg.db, ont="ALL",
	            pvalueCutoff=0.05, keyType="SYMBOL", verbose=FALSE)

	# 保存结果表
	enrich_go_gsea_df<-enrich_go_gsea@result
	fwrite(enrich_go_gsea_df,"enrich_go_gsea_df.tsv", sep="\t")
	# ont = "ALL"表示同时对 MF、BP、CC 三大类都做富集，如果只关心其中一类，可以改成"BP"、"MF"或"CC"。
	```
	2) 可视化：气泡图 + 单通路富集曲线
	```R
	# 气泡图
	dotplot_enrich_go_gsea<-dotplot(enrich_go_gsea, showCategory=10, orderBy="GeneRatio")
	ggsave("dotplot_enrich_go_gsea.png", dotplot_enrich_go_gsea,
	   device="png", units="cm", width=16, height=18)
	# 单通路富集曲线
	# 从上面保存的enrich_go_gsea_df里挑一个你感兴趣的GO term编号
	GOID<-"GO:0010634"
	gsea_plot<-gseaplot2(enrich_go_gsea, geneSetID=GOID,
	           title=subset(enrich_go_gsea_df, ID==GOID)$Description)
	ggsave(paste0("gsea_plot_", gsub(":","", GOID),".png"), gsea_plot,
	   device="png", units="cm", width=18, height=16)
	```
	3) KEGG 富集（GSEA 方法）
	```R
	# KEGG 要求用 Entrez ID，不能直接用基因名
	# 把基因名转成Entrez ID（KEGG分析的硬性要求）
	entrez_ids<-mapIds(
	 x=org.Mm.eg.db,# 人换org.Hs.eg.db，大鼠换org.Rn.eg.db
	 keys=names(logfc),
	 keytype="SYMBOL",
	 column="ENTREZID",
	 multiVals="first"# 一个基因名对应多个Entrez ID时，取第一个
	)
	names(logfc)<-entrez_ids
	logfc<-logfc[!is.na(names(logfc))]# 去掉转换失败（没匹配上）的基因
	# KEGG物种代码："mmu"=小鼠, "hsa"=人, "rno"=大鼠
	enrich_kegg_gsea<-gseKEGG(geneList=logfc, organism="mmu")
	enrich_kegg_gsea_df<-enrich_kegg_gsea@result
	fwrite(enrich_kegg_gsea_df,"enrich_kegg_gsea_df.tsv", sep="\t")
	```

	1) GO 富集（ORA 方法）
	```R
	# 筛出上调的显著差异基因
	deg_up<-deg[log2FoldChange>log2(fc_threshold)&padj<p_threshold]$V1
	# deg_dn <- deg[log2FoldChange < -log2(fc_threshold) & padj < p_threshold]$V1  # 下调基因
	enrich_go_fet_up<-enrichGO(gene=deg_up, OrgDb=org.Mm.eg.db, keyType="SYMBOL",

	enrich_go_fet_up_df<-enrich_go_fet_up@result
	```

8. 解读富集结果
> 拿到一堆富集结果表之后，建议从三个角度交叉检查，而不是只看某一列数字：
> 统计显著性：
> 	优先看校正后的 p 值（FDR/p.adjust），而不是原始 p 值；
> 	留意通路里基因集的大小——特别小或特别大的基因集，统计结果的稳健性通常更容易受极端值影响；
> 	同一个生物学主题如果在 ORA 和 GSEA 结果里都出现，可信度会更高。
> 生物学相关性：
> 	优先关注和你实验背景强相关的通路，而不是一股脑把排名最靠前的都当结论；
> 	留意通路之间的层级/重叠关系（比如某个大类通路下面套了好几个子通路，同时显著可能只是同一批基因反复被计算）；
> 	也别忽略一些意料之外但逻辑上说得通的通路，可能是新的线索。
> 技术细节：
> 	确认背景基因集（background gene set）选得是否合理，默认背景（全基因组）不一定适合所有实验设计；
> 	确认多重检验校正方法用的是什么（默认通常是 BH 法），不同校正方法结果会有差异；
> 	通路富集结果之间存在天然的冗余和重叠，不要把"显著通路数量多"直接等同于"生物学意义更强"。
